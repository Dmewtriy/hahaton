# Кабинет HR: рабочие действия

Откройте `/dashboard` и войдите рабочим ключом HR. В будущем MAX Mini App откроет этот же кабинет по проверенному аккаунту без ввода ключа. Bootstrap нужен для начальной выдачи ролей, а не для работы с личными данными.

## Начальная настройка

1. В «Доступ и роли» создайте HR и руководителей, назначьте площадки. «Все площадки» означает всю компанию. Выдайте одноразовые приглашения в MAX. Отдельное доверенное право управления доступом выдаёт его обладатель; обычному HR оно для ежедневной работы не требуется.
2. В «Площадки» задайте название, часовой пояс, календарь, материалы и сценарий адаптации. В «Подразделения» добавьте отделы и руководителей.
3. В «Документы» загрузите файлы и задайте доступ. Статус обработки виден в списке. «Заглушка ML» означает тестовый индексатор, который не читает документы.
4. В «Адаптация» отредактируйте сценарий: порядок шагов, сроки относительно выхода, опросники, файлы и ручной запуск. Сохранение публикует новую версию, история сохраняется.
5. В «Сотрудники» добавьте анкету, выберите рекрутера, отдел, руководителя, дату выхода и часовой пояс. Выпустите приглашение в MAX.

## Изменение и удаление

В списках есть поиск, фильтры, кнопки редактирования и архив. Удаление означает архивирование; восстановление доступно на вкладке «Архив». Площадку или подразделение с действующими сотрудниками сначала нужно освободить. Отключение сотрудника блокирует доступ, будущие отправки и активные диалоги, сохраняя ответы.

Для обновления регламента нажмите «Загрузить новую версию». Предыдущая версия автоматически уйдёт в архив и сразу перестанет быть разрешённым источником ответов. Если индексация завершилась ошибкой, доступна повторная обработка. Содержание и качество индексации обеспечивает подключённый ML-сервис.

## Опрос и рассылка

1. В «Опросники» создайте название и вопросы: один вариант, несколько вариантов, оценка или свободный ответ. Для оценки можно запросить комментарий ниже заданного порога, для варианта — комментарий и сигнал HR.
2. Нажмите «Отправить» либо создайте рассылку в «Рассылки». Выберите всех сотрудников, площадки, отделы или конкретных людей. При необходимости добавьте файлы и дату отправки.
3. Нажмите «Проверить получателей», сохраните черновик. До отдельного подтверждения отправка не начинается.
4. Нажмите «Запустить» и подтвердите число получателей. Если состав команды изменился, сервер потребует новый предпросмотр. После публикации доступны статусы и ответы; редактирование шаблона уже опубликованный опрос не меняет.
5. Незавершённые опросы напоминают о себе по настроенным срокам. При занятом диалоге следующий опрос ожидает в очереди. Отмена рассылки сохраняет уже полученные ответы.

## Обращения и аналитика

Если бот не нашёл подтверждённого ответа или ML недоступен, он честно сообщает об этом и передаёт вопрос закреплённому HR. Опросы и рассылки при этом продолжаются.

В «Переписка HR» по умолчанию показаны ваши сотрудники. Красная точка означает новые сообщения или сигналы. Откройте человека по имени — там вся история, включая старые обращения. Напишите ответ; окно останется открытым. Новые сообщения не стирают набираемый черновик. «Отметить обращения решёнными» — отметка для HR, а не условие возобновления бота.

Сотрудник отправляет каждое сообщение через `/hr текст`, либо `/hr`, затем одно сообщение. Кнопка «Ответить HR» работает так же. `/cancel` отменяет ввод, `/resume` возвращает к вопросу опроса. Если пришёл новый опрос, отвечайте на него; для HR используйте явное `/hr текст`. Когда шаг адаптации просит рассказ для рекрутера, следующий текст автоматически направляется HR, без обращения к ИИ.

Режим «Вся моя область» открывает разрешённых по роли сотрудников, а «Архив» — историю отключённых. При смене закреплённого HR сотрудник переходит в список нового рекрутера, история сохраняется. Курсор прочитанного отдельный для каждого HR.

Без мини-приложения HR может отвечать в MAX: `/reply ID текст`, отмечать `/close ID`, получать сводку `/dashboard`. Уведомление содержит ID и контекст. Подсказки при вводе `/` регистрируются командой `python -m korsik.cli sync-commands`; в текущем боте они уже настроены после обновления. Руководитель подразделения получает сводку только по своим сотрудникам.

На «Обзоре» показаны этапы, незавершённые опросы, обращения, темы и риски. Числа рассчитываются backend из БД. Глобальный HR настраивает правила сигналов и еженедельный дайджест в «Настройки». ML-заглушка не даёт настоящую оценку настроения.

## Проверка без установки MAX

Используйте отдельную базу с `KORSIK_TRANSPORT=mock`, `KORSIK_ML_MODE=stub`, `KORSIK_ENABLE_DEMO=true`. Там можно работать с кабинетом, отправлять события через Swagger `/api/demo/events`, обрабатывать очередь `/api/demo/tick`, смотреть `/api/demo/outbox` и менять время `/api/demo/clock` техническим ключом. Автотесты создают собственные временные базы и не отправляют сообщения в MAX.

Для коллег с MAX достаточно запущенных на ноутбуке API, worker и poll с действующим токеном. Самому разработчику устанавливать MAX не требуется. Мини-приложению в телефонах коллег позже потребуется публичный HTTPS.
