# Данные сценариев

Файл `examples/onboarding.json` можно загрузить через кабинет или POST `/api/scenarios`. API отклоняет неизвестные поля, повторные ID, неправильные шкалы, неизвестные survey_id и опасные шаблоны. Python-код, eval и выражения в описании сценария не выполняются.

Минимальный пример:

```json
{
  "name": "Новый филиал — адаптация",
  "version": 1,
  "steps": [
    {
      "id": "welcome",
      "text": "Здравствуйте, {name}! Добро пожаловать в {branch}.",
      "informal_text": "Привет, {name}! Добро пожаловать в {branch}.",
      "schedule": {"working_day": 1, "at": "10:00"},
      "resource_keys": ["map", "food"]
    }
  ],
  "surveys": []
}
```

Сначала создать версию, затем назначить её `scenario_id` в площадке. Для редакции повысить version. Step ID — постоянная идентичность логического действия, а не порядковый номер: это позволяет не повторять выполненный шаг после публикации новой версии.

## Поля шага

- `kind`: message, survey или manager_reminder.
- `schedule.anchor`: hire или probation_end.
- `months`: календарные месяцы с ограничением последним днём короткого месяца.
- `days`: календарное смещение; отрицательное число — до выхода.
- `working_day`: N-й рабочий день начиная с даты после применения months/days.
- `at`: локальное HH:MM сотрудника.
- `next_workday`: перенести календарное событие на следующий рабочий день.
- `branch_codes`, `categories`: фильтры; пустой список означает все.
- `manual`: не запускать до действия закреплённого рекрутера.
- `text`, `informal_text`: варианты общения. Если неформальный отсутствует, используется основной.
- `resource_keys`: ключи материалов площадки. Нет материала — честное сообщение об отсутствии.
- `document_ids`: ID загруженных вложений; перед отправкой ещё раз проверяется доступ получателя.
- `survey_id`: обязательная ссылка для kind=survey.

Поддерживаются только `{name}`, `{branch}`, `{department}`. Строки материалов площадки не исполняются как шаблоны. Не используйте step ID заново для другого действия.

## Вопросы

`single` и `multiple` используют options с уникальными ID. `rating` принимает целые minimum..maximum. `text` принимает непустую строку. Необязательные условия:

```json
{
  "id": "support",
  "text": "Оцените поддержку коллег",
  "kind": "rating",
  "minimum": 1,
  "maximum": 10,
  "comment_below": 8,
  "comment_prompt": "Какой поддержки не хватило?"
}
```

Вариант ответа может содержать `needs_comment`, `notify_hr`, `reply`. Несколько выбранных вариантов с этими признаками создают один условный комментарий и один структурный сигнал. `reminder_days: [1, 2]` задаётся у опроса.

## Сопоставление с исходным XLSX

Основной лист содержит 70 заполненных строк; 68 строк содержимого после заголовков. Исходные значения доступны в `examples/source_scenario_rows.json` для проверки, без исправления оригинала. Даты в столбце A сохранены как есть и не используются для расписания.

Пример сценария объединяет соседние реплики в 28 логических шагов и 7 опросов. В нём нет отсутствующих у команды изображений, карт и персональных планов: их надо добавить через материалы площадки/вложения. Формулировки приведены к нейтральному «вы», подробный текст можно заменить через конфигурацию.

Принятые для первой версии решения, требующие подтверждения заказчика:

1. Противоречивый «опрос по итогам двух месяцев» сохранён на 1 месяц + 3 недели, как в столбце времени. Название подчёркивает впечатления, не юридический факт окончания двух месяцев.
2. «Первый день второго месяца» трактуется как дата выхода + один календарный месяц, а не первое число следующего месяца.
3. Для всех площадок пример предлагает общий набор вариантов улучшения без обещания удалённой работы. Разные наборы можно задать двумя опросами и фильтрами шагов.
4. Проверка документов даёт ссылку на согласованный перечень; не утверждает, что все перечисленные в XLSX документы обязательны для каждого кандидата.
5. Окончание адаптации задаётся явно; по умолчанию +3 календарных месяца. Решение о прохождении испытания бот не принимает.
6. Праздники, переносы, сменные графики, недостающие материалы и конкретные контакты заполняет HR.

Для нового филиала достаточно создать площадку, настроить материалы и выбрать версию сценария. Упоминание кода филиала в Python не требуется: три кода в seed — только демонстрационные исходные данные.
