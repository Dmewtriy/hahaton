# Проверка версии v0.4

Сервер, PostgreSQL и worker работают на ноутбуке. MAX на ноутбук устанавливать не нужно: коллеги открывают бота на своих устройствах. ML можно оставить в режиме `stub`; он честно сообщает, что подтверждённого ответа нет, и создаёт обращение HR.

## Запуск

Из каталога `back`, с существующим `.env`:

```powershell
docker compose --profile max-poll up -d --build
docker compose exec api python -m korsik.cli install-v04
docker compose exec api python -m korsik.cli sync-commands
```

Если это новый компьютер: скопировать `.env.example` в `.env`, задать собственные `POSTGRES_PASSWORD`, `KORSIK_BOOTSTRAP_TOKEN`, токен MAX и имя бота без `@`. Не использовать один токен MAX одновременно с несколькими экземплярами poll. `KORSIK_ML_MODE=stub`, `KORSIK_TRANSPORT=max`. Ключи не отправлять в Git. Локальный кабинет: `http://127.0.0.1:8000/dashboard`.

Установленный маршрут не назначает себя всем площадкам автоматически. HR выбирает его в карточке площадки. Для новой площадки в той же карточке можно создать собственную конфигурацию по образцу ГрПП, ГТП или Лужников. Исходный маршрут: 21 сценарий, 55 обязательных строк. Его карточки, вопросы, реакции и расписание редактируются в «Адаптация» → новая версия. Загрузка обязательных материалов — отдельный шаг подготовки.

## Подготовка HR

1. Назначить четыре рабочие роли: employee, hr, manager, hr_head. Право manage_access выдаётся отдельно. HR работает в назначенной области, `*` означает все площадки компании.
2. Создать площадки и подразделения. Часовой пояс выбирается из IANA-справочника; он влияет на даты и время отправок. В анкете сотрудника выбрать отдел, HR, руководителя, дату выхода, окончание адаптации; добавить персональный план и подготовленные ИТ-доступы.
3. В «Доступ и роли» указать личную ссылку рекрутера. В карточке площадки при необходимости разрешить других получателей обращений; они должны иметь доступ к площадке.
4. Загрузить документы/изображения, дождаться статуса обработки и публикации. В «Материалы маршрута» назначить файлы позициям реестра. Картинки — PNG/JPG, питание — PDF. Реестр отражает 38 потребностей источника, включая дополнительные; это не 38 предоставленных оригиналов файлов.
5. Проверить «Материалы маршрута» → требуют внимания HR. По умолчанию пропущенные шаги при позднем подключении ждут ручного запуска. Отсутствующие файлы не заменяются вымышленным контентом и не считаются успешно отправленными.
6. Выпустить приглашение и передать его коллеге. Проверить `/menu`, `/hr сообщение`, `/cases`, `/ask вопрос`, `/resume`, `/food`.

## Дедлайны и напоминания

Дедлайн задаётся у рассылки HR в поле окончания (`expires_at`); без значения срока нет. Он является абсолютным временем с часовым поясом и сохраняется в снимке назначенного опроса. После наступления срока worker помечает назначение/опрос как истёкшие, а обработчик ответа повторно проверяет срок даже до очередного прохода worker. Частичные ответы остаются в истории и экспорте. Истёкшие опросы освобождают очередь; напоминания после дедлайна не отправляются.

Напоминания в пользовательском опроснике задаются числом дней после фактического начала. У исходных обязательных опросов v0.4 автоматические напоминания выключены: R070 дополнительная строка, она не включается скрыто в базовый маршрут. Будущая необязательная кампания с напоминаниями настраивается HR отдельно.

Окончание испытательного срока и дедлайн опроса — разные события. Естественное завершение адаптации не уничтожает уже начатые опросы и обращения. Новые шаги адаптации не создаются; ранее назначенные, но не начатые требуют решения HR. Общие рассылки, документы и переписка остаются доступны. Явная остановка HR или блокировка аккаунта отменяет соответствующую работу.

## Выгрузки

«Выгрузки» → выбрать опрос и версию, период по плановой дате назначения, часовой пояс, площадку/подразделение → предпросмотр → CSV/XLSX. CSV — UTF-8 BOM и `;`, строки назначений с ответами, комментариями, статусом и метаданными среза. XLSX — три листа: «Результаты», «Сводка», «Описание». Сохраняются частичные ответы; оценки — числа; отсутствие ответа не подменяется нулём. Из расчётов исключаются отменённые назначения, но их строки видны.

Средняя оценка считается отдельно для каждого вопроса по принятым ответам, включая частичные. Завершение: завершённые / уже наступившие неотменённые назначения. В множественном выборе доля считается от ответивших, поэтому сумма может быть больше 100%. Файл содержит версию и правила расчёта; ML для выгрузки не вызывается. Ссылка скачивания действует 60 секунд; права повторно проверяются при скачивании. Максимум 10 000 назначений — при превышении нужно сузить выборку.

В отдельных столбцах находятся состояния ИИ-помощи и связанных с опросом обращений; подтверждённое решение отличается от архивного/исторического закрытия. Свободная переписка HR автоматически в экспорт не добавляется. При изменении данных после предпросмотра сервер отклоняет его hash с сообщением обновить предпросмотр. PostgreSQL формирует согласованный срез в REPEATABLE READ. Время нового комментария сохраняется отдельно: комментарий, появившийся после среза, не включается; у старых комментариев точное отдельное время неизвестно.

Раздел «Обработка» показывает, какие свободные ответы и комментарии обработаны, какие ждут ML и какие завершились ошибкой; HR может повторить неудачный анализ. Там же видна отправка уведомлений HR, включая отсутствие привязки MAX. Состояния «обращение зарегистрировано», «уведомление отправлено в MAX» и «человек прочитал» не смешиваются.

## Подстановки

Список отображается в «Настройки» и редакторе сценария. Поддерживаются `{name}`, `{branch}`, `{department}`, `{recruiter_name}`, `{manager_name}`, `{hire_date}`, `{probation_end}`, `{timezone}`. Значения берутся из карточек сотрудника, площадки и назначенных пользователей в момент формирования сообщения. Названия ключей фиксирует backend; значения меняет HR через карточки. Произвольные выражения, доступ к атрибутам и исполняемый код в шаблонах не допускаются.

## Обращения и проверка решения

`/hr текст` отправляет одно сообщение. Если открыто несколько обращений, бот предлагает выбрать нужное либо создать новое. Есть `/cases`; кнопка под ответом HR относится к конкретному обращению. Выбор другого разрешённого HR не делает обращение анонимным; исходный и прежний HR сохраняют доступ к нему.

Во время опроса неоднозначное сообщение, похожее на вопрос, сначала вызывает выбор намерения: ответ/комментарий, отдельный вопрос ИИ либо сообщение HR. До выбора оно не записывается в ответ и не передаётся дальше. Команды `/ask` и `/hr` задают намерение сразу; `/resume` возвращает текущий вопрос. Подтверждения относятся к конкретной попытке помощи, поэтому старые кнопки после повтора не меняют новый результат.

В кабинете HR выбирает сотрудника, затем конкретное обращение. Обычный ответ цитирует вопрос. «Предложить решение» переводит только это обращение в ожидание подтверждения. «Да» сотрудника закрывает текущую ревизию; «Нет» возвращает тот же номер в работу. Старые кнопки и молчание не закрывают обращение. Архивирование — отдельный исход и не учитывается как подтверждённое решение.

## Проверки

```powershell
python -m pytest -q
ruff check src tests
```

Основные новые проверки: `tests/test_v04_release.py`. Они проходят маршруты всех площадок с явно синтетическими тестовыми вложениями и mock-транспортом. Это проверяет backend, но не заменяет приёмку оригинального контента, реального ML, MAX на устройствах коллег и нагрузочные испытания.
